# AGENTS.md

## Cursor Cloud specific instructions

Python trading backtester + paper-trading bot + read-only Flask dashboard. Python 3.12, deps in `requirements.txt`. The startup update script creates a virtualenv at `.venv` and installs `requirements.txt`, so activate it before running anything:

```bash
. .venv/bin/activate
```

### Services / entry points
- **Backtester CLI** — `python run_backtest.py --symbol GC=F --entry-tf 1d --regime-tf 1d --strategy all` (see `README.md` / `INSTRUKTIONER.md` for all flags). Default `--entry-tf` is `30m`.
- **Paper-trading bot** — `python run_live.py --once --strategy macd_pullback --symbol GC=F` (paper only, no broker). Writes state/logs to `data/live/`.
- **Dashboard (web app)** — `python dashboard/app.py`, serves on `0.0.0.0:8080` (read-only view of `data/live/` state). Override port with `DASHBOARD_PORT`; set `DASHBOARD_PASSWORD` to require basic auth (open if unset).
- **Global Value Hunter & Arbitrage Bot** — `python run_global_hunter.py --once --capital 400000` (single scan+filter+governor pass, prints decisions, no orders placed) or `--serve` to run the full pipeline forever. Separate package at `global_hunter/` (see `.cursorrules` for the architecture mandate); paper-only by default, writes to `data/live/global_hunter/`. Run `python -m global_hunter.model` to print the aggregated 30 000 SEK/month math model, or `python -m global_hunter.micro.registry` to print the 10-strategy Micro-Agent portfolio with each one's edge rationale. Pipeline: `[scanner/` (5 macro modules: `GlobalMarketNeutralArbitrage`, `PredictiveValueAccumulation`, `OpportunisticMarketScraper`, `ingestion/GlobalIngestionEngine` config-driven feeds, `events/AlphaEventScanner` news-driven) `+ micro/MicroAgentSwarm]` (10 small independent strategies, each wrapped in `micro/IsolatedExecutionWrapper` with its own circuit breaker) -> `legal/LegalAndTaxFilter` (sizing scaled by `micro/CapitalAllocator`'s real-time health/performance multiplier) -> `governor/ExecutionGovernor` (autonomous capital reallocation/preemption between modules) -> `engine/DynamicExecutionEngine`.
- `global_hunter/micro/agents/*.py`: 5 are LIVE (real API/data verified), 5 are intentionally-idle SKELETONs pending a paid/partner data source (odds API, options IV, gift-card marketplace, EUA futures curve, earnings-surprise feed) -- each logs one warning and returns `[]` rather than raising, so the swarm and `IsolatedExecutionWrapper`'s circuit breaker never mistake "no data source configured" for "broken module."
- **New source registration**: any new `Opportunity.source` string MUST be added to `global_hunter/legal/rules_se_ab.py`'s `KNOWN_VENUES` (or match a `KNOWN_SOURCE_PREFIXES` entry) or `LegalAndTaxFilter` fail-closes and silently rejects everything from it -- this bit us once already when `GlobalIngestionEngine`/`AlphaEventScanner` were added.
- `global_hunter/ingestion/feeds/*.yaml` config-driven feeds: add a new marketplace by copying a template, no Python changes (see the module docstring in `global_hunter/ingestion/config_loader.py`). Files with `_template` in the name are unfilled placeholders and are skipped by `load_feed_configs()` by default.
- `global_hunter/events/gdelt.py`'s `GdeltClient` self-throttles to one request per ~5.5s (GDELT's own stated courtesy limit) -- `AlphaEventScanner.scan()` deliberately iterates topics sequentially (not `asyncio.gather`) so this throttle produces one predictable queue; a full scan over N topics takes roughly N x 5.5s (plus a second call per topic that trips its volume threshold).

### Non-obvious notes
- **Market data cache** lives in `data/cache/` (gitignored). It is pre-populated in the VM snapshot and also shipped as `data_cache_10y.tar.gz`. If a symbol/timeframe has <300 cached bars, the loader re-downloads live from Yahoo/Binance/Dukascopy (network egress works in this environment). No API keys are required for the default flows; `POLYGON_API_KEY` (in `.env`) is optional and only upgrades stocks intraday data (falls back to Yahoo without it).
- `run_live.py` uses `--timeframe` (not `--entry-tf`). Running the paper bot with `--timeframe 1d` (entry == regime timeframe) hits a pre-existing `KeyError: 'ema_slow'`; use the default `30m` entry / `1d` regime documented flow instead.
- There is **no formal lint config or pytest suite** (`scripts/test_*.py` are ad-hoc research scripts, not unit tests). Use `python -m compileall backtest strategies live dashboard global_hunter config.py run_backtest.py run_live.py run_global_hunter.py` as a quick syntax check.
- Dependency versions float (`pandas>=2.0`, `numpy>=1.24`); the code runs on current pandas 3.x / numpy 2.x. `aiohttp>=3.9` and `pyyaml>=6.0` were added for `global_hunter/`'s async venue adapters and config-driven ingestion feeds (everything else in the repo uses stdlib `urllib` via `backtest/http_client.py`).
- **Binance's `api.binance.com`/`fapi.binance.com` geo-block this VM's egress IP with HTTP 451** ("restricted location"). `global_hunter`'s spot venue adapter therefore uses the unrestricted mirror `data-api.binance.vision` instead. There is no equivalent unrestricted mirror for futures/funding endpoints (`fapi.binance.com`) at the time of writing — that adapter fails soft (skips the pair) when blocked; verify reachability from wherever this actually runs long-term.
